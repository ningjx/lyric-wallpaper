# Windows 原生歌词壁纸

## 运行发布包

下载后直接运行 `LyricWallpaper-win-x64.exe`。右键托盘图标选择「打开设置」，也可以双击图标打开主窗口。托盘菜单提供播放状态、歌词服务设置、重启歌词服务、开机自启、日志目录、关于和退出。程序在主屏显示。

从旧版更新时，先通过托盘菜单退出旧版，再运行新的 EXE。

- **壁纸**按背景、歌词排版、空间层次、玻璃、高光与阴影分组。「背景来源」里选图片会固定显示该图，选文件夹会随机轮播，也可切回纯色。布局、缩放、位置和歌词效果可实时调节，改动自动写入 `%LOCALAPPDATA%\LyricServer\wallpaper.json`。
- **测试滚动**可以从设置窗口标题区或托盘菜单开启。演示歌词和译文会在桌面上循环滚动，方便一边改参数一边看效果。关闭后恢复播放器歌词或时钟，每次启动默认关闭测试模式。
- **开机自启**可在设置窗口左下角或托盘菜单切换，两处状态同步。开启后，当前 Windows 用户登录时会启动程序。移到新目录后，在新位置打开程序并重新开启即可更新启动路径。
- **歌词服务**可以切换播放器、调整优先级和采样间隔，选择和排序歌词源，以及配置超时、重试和缓存目录。停止编辑约 0.5 秒后，程序自动写入有效配置并合并重启采集，壁纸窗口继续运行。托盘的日志目录包含 `native-worker.log`。
- **编辑桌面控件**可在桌面上左键长按任意时钟约 350 毫秒进入，也可从托盘菜单或用 `Ctrl+Alt+E` 打开。长按进入后可继续按着拖动，松手仍停留在编辑模式。
- 进入编辑时，右侧控件栏默认展开，预览卡片以当前壁纸和玻璃参数渲染。点击时钟预览即可生成并选中新实例，程序优先在控件栏左侧找空位。控件栏可以收起。选中控件后，设置直接展开，可以拖动控件或拉四角缩放。点控件右上角的 × 或按 Delete 删除。方向键移动 1 像素，按住 Shift 移动 10 像素。`Ctrl+Tab` 切换选中，`Ctrl+Z` 撤销、`Ctrl+Y` 重做。单击操作区以外的位置即可退出编辑，桌面图标也会照常响应点击。Esc 取消当前拖动或退出编辑。
- 控件自动保存到 `%LOCALAPPDATA%\LyricServer\widgets.json`。旧时钟保留位置、样式和闲时显示规则。新时钟默认常驻，可在样式中切换为仅闲时显示。首次保存新版格式时，旧配置会备份为 `widgets.json.v1.bak` 或 `widgets.json.v2.bak`。
- 每个时钟都可单独开启「文字自动反色」：亮处用黑字，暗处用白字。关闭后恢复该控件之前选的颜色，不影响歌词文字或其他时钟。
- 控件设置卡片随选中控件调整宽度，太窄时保留可操作的最小宽度。卡片使用浅色磨砂背景，随位置显示下方壁纸的模糊底图。

播放器采集和歌词查询在同一个 .NET 进程的后台运行。支持网易云音乐、Microsoft Store 版 Apple Music，以及网易云、QQ 音乐和本地 LRC 歌词源。沿用 `%LOCALAPPDATA%\LyricServer\config.json` 和配置中的歌词缓存目录，能读取上一版下载的原词、译文和逐字歌词。

## 构建与开发

在安装了 .NET 10 SDK 的 Windows x64 机器上执行以下命令，生成自包含的单文件 `release/LyricWallpaper-win-x64.exe`。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-native-wallpaper.ps1
```

也可从源码启动。可以先退出正在运行的动态壁纸，避免两个程序同时向桌面呈现。

```powershell
dotnet build native-wallpaper/NativeWallpaper.csproj -c Release
& .\native-wallpaper\bin\Release\net10.0-windows10.0.19041.0\NativeWallpaper.exe
```

参数可组合使用。

| 参数 | 用途 |
| --- | --- |
| `--preview` | 打开同尺寸的普通预览窗口，按 Esc 提前退出。 |
| `--settings` | 启动时打开设置主窗口。 |
| `--edit-widgets` | 启动时进入桌面控件编辑。 |
| `--demo` | 使用固定歌词和时间轴，默认 60 秒后退出。 |
| `--test-scroll` | 启动时直接开启可切换的测试滚动，继续运行歌词采集。 |
| `--still` | 使用演示歌词并固定在同一句，用于测量静止场景。 |
| `--config 路径` | 使用指定的歌词服务配置。 |
| `--fps 100` | 设置动画帧率上限，默认 60。 |
| `--wallpaper-config 路径` | 指定壁纸配置文件，也可为演示模式指定对比参数。 |
| `--seconds 30` | 指定测试时长。 |
| `--report report.json` | 保存分辨率、呈现路径、桌面层级采样和动画帧间隔。 |
| `--capture frame.png` | 将首个 D3D11 帧保存为 PNG，可单独用于检查画面。读回会阻塞 GPU，性能采样时省略此参数。 |

原生版在主屏呈现滚动 LRC、译文、歌曲信息和空闲时钟。默认的时钟居中，可添加多个时钟并分别保存位置和样式。设置窗口采用 WPF UI 的 Win11 Fluent 主题，桌面壁纸在独立线程由 D3D11 渲染。

- 「歌词排版」的渲染像素比（DPR）范围为 0.50–2.00，1.00 是屏幕原生像素。它调整 D3D11 交换链的缓冲尺寸，由 DXGI 缩放到原来的桌面区域。
- 「玻璃」的背景模糊在半径大于 0 时生效：普通模式缓存多级缩小的背景，高质量模式使用可分离高斯模糊。开启「渐进模糊」可保留清晰边缘、柔化中心，也可用于背面歌词，因为只模糊壁纸；关闭时维持背面模式不模糊的行为。时钟、歌词和 Dock 预览共用背景缓存，玻璃外仍显示原图。
- 「歌词排版」的自适应文字对比度默认开启，背景和文字颜色太接近时增加深色或浅色细描边，不换字色。色散可选关闭、原有 RGB、七路光谱；七路更耗采样，默认不启用。开启「色相染色」后，染色会先替换色相，再少量叠色；染色不透明度为 0 时无效果。
- 玻璃边缘按镜片曲线折射。「镜片立体折射」让折射方向同时参考卡片中心，与「空间层次」里的歌词景深分开控制。「连续曲率圆角」可切换回普通圆弧；同一轮廓用于折射、高光和阴影。
- 「高光与阴影」的默认和纯净模式以加法提亮边缘；环境模式按光线方向提亮一侧、压暗另一侧。内阴影默认关闭，可调不透明度、模糊半径和偏移，不改变原有的外阴影。原生版用解析轮廓和距离近似完成这些效果，不为每张卡片生成额外的遮罩纹理。

## 源码模块

| 目录 | 职责 |
| --- | --- |
| `App/` | 组装应用，协调 WPF 线程、桌面渲染线程及后台歌词服务。 |
| `Playback/` | 播放器采集、仲裁、歌词查询和缓存，对外提供只读播放快照。 |
| `Wallpaper/` | 背景与轮播、歌词时间轴、排版及测试滚动。 |
| `Widgets/` | 控件实体、类型登记、布局、可见性、编辑命令与撤销记录。时钟的专属选项位于 `Widgets/Clock/`。 |
| `Scene/`、`Rendering/` | 场景和材质数据、文本图集、D3D11 合成。 |
| `Platform/Windows/` | Explorer 附着、DPI 与桌面命中区域、全局热键及开机自启。 |
| `Presentation/`、`Storage/` | 设置、托盘、控件编辑和右侧 Dock，以及各配置文件的独立读写与迁移。 |

Dock 从 `WidgetCatalog` 读取控件类型。使用现有文字玻璃卡片的控件可注册自己的默认参数、内容和刷新时间，并按需在 `WidgetInspectors` 注册属性界面。控件实例的数组顺序决定图层顺序。旧格式由 `WidgetStore` 转换，未知控件类型随配置原样保留。

可从仓库根目录运行原生回归检查，覆盖配置迁移、控件布局、撤销、可见性和歌词服务的启动与重载。

```powershell
dotnet run --project native-wallpaper.Tests/NativeWallpaper.Tests.csproj -c Release
```

## DPR 和全场模糊实测

以下数据来自局部与全场模糊的早期采样实现。GTX 1060 5GB，主屏 1920 × 1080，桌面图标后方的 DXGI blt 路径。每档在固定背景和固定歌词演示下以 60 FPS 为上限，采样 24 次 Windows GPU Engine 和 GPU Process Memory 计数器。表中的 GPU 是壁纸进程最忙引擎的平均利用率，包含两句歌词之间的静止时间。关键档位以相反顺序测了两轮，区间为这两轮的结果。

| DPR | 缓冲尺寸 | 模糊半径 24 的方式 | GPU | 平均专用显存 |
| --- | --- | --- | ---: | ---: |
| 0.75 | 1440 × 810 | 全场 | 0.47%（一轮） | 87.8 MiB |
| 1.00 | 1920 × 1080 | 局部 | 1.44–1.53% | 88.8 MiB |
| 1.00 | 1920 × 1080 | 全场 | 0.60–0.65% | 93.5 MiB |
| 1.50 | 2880 × 1620 | 局部 | 1.49–5.03% | 98.7 MiB |
| 1.50 | 2880 × 1620 | 全场 | 1.30–2.28% | 108.5 MiB |

全场模糊各档只重建了一次缓存。1.00 倍下，两轮都是全场模糊的 GPU 利用率更低，专用显存多约 4.8 MiB。1.50 倍的全场档处理的像素数是 1.00 倍的 2.25 倍，GPU 利用率和专用显存在两轮都更高。同一 1.50 倍下，局部与全场的 GPU 利用率高低在两轮互换。测量范围是应用进程，换图重建成本、DWM 和总功耗需另采样。

## 旧原型性能基线

以下是接入采集前的固定歌词原型基线。机器为 Windows 11 Build 26300.9457、GTX 1060 5GB、1920 × 1080 / 100 Hz。原型通过 `Progman` 层使用 DXGI blt 呈现，62 秒内的 62 次层级检查全部通过，滚动提交间隔 P50 为 10.0 ms，P95 为 19.7 ms。

使用 Wallpaper Engine 2.8.42 的 `openWallpaper -playInWindow` 和原型的 `--preview`，在同一台机器上分别以实际画布 1920 × 1080、显示器 100 Hz 运行。对照来自迁移前的 Vite 构建临时副本，分别启用内置的 `demo` 和 `still` 场景。CEF 报告的 WebGL 后端是同一张 GTX 1060 上的 ANGLE D3D11。每组预热后取约 30 秒 Windows 进程及 GPU 计数器。Wallpaper Engine 统计纳入主进程及对照窗口的五个 CEF 进程，原有壁纸的独立 CEF 进程组未计入。表格统计的是测试应用进程。 [Wallpaper Engine 命令行说明](https://help.wallpaperengine.io/en/functionality/cli.html)

| 指标 | Wallpaper Engine 滚动 | 原型滚动 | Wallpaper Engine 静止 | 原型静止 |
| --- | ---: | ---: | ---: | ---: |
| CPU（单个逻辑核 = 100%） | 51.25% | 1.00% | 5.62% | 0.05% |
| 最忙 GPU 引擎平均利用率 | 6.86% | 2.50% | 0% | 0% |
| 平均专用显存 | 250.4 MiB | 114.7 MiB | 173.2 MiB | 106.3 MiB |
| 采样结束时的私有内存 | 674.1 MiB | 247.3 MiB | 348.0 MiB | 257.9 MiB |

滚动场景包含两句之间的等待时间。GPU 利用率是每次采样时测试进程最忙的 GPU 引擎占用率，再取采样均值。专用显存取自 Windows 的 GPU Process Memory 计数器。原型静止运行约 39 秒时只提交了首帧，CEF 的静止场景每秒仍执行约 85 次动画回调。画面使用相近的效果，原型的玻璃和排版为重新实现。这里的对照限于预览窗口，桌面合成器 DWM 和系统功耗需要单独采样。

同次验证中，原型的 Release 构建通过，Web 壁纸的 27 项测试和 Vite 构建也通过。
